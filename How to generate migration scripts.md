# GENERATE MIGRATION SCRIPTS

We recommend using the AdminUI migrations tool but if you prefer to manage the migration scripts on your own, here are the instructions.

Before running the migration scripts, you need 2 things:
1. Add Microsoft.EntityFrameworkCore.Design package
2. Make sure you have the right DbProvider and ConnectionStrings in the appsettings.json file

## To run just the latest migration

The specific migration names can be found here:

- [SqlServer](./SqlServer%20migration%20names.md)
- [MySql](./MySql%20migration%20names.md)
- [PostgreSql](./PostgreSql%20migration%20names.md)

If you just want to generate the script for a specific migration, you can do it following this pattern:

```bash
dotnet ef migrations script <FromMigration> <ToMigration> --context <DbContextName> --output ./SqlScript.sql
```

**Very Important**:

- **The migration of `<FromMigration>` is not included**: The `<FromMigration>` migration is treated as the starting point, so the generated script will contain the migrations needed to move from that migration to the target migration.
- **The script is generated per DbContext**: If there are multiple DbContexts implicated in the migrations you need to run, you will need to run that command on each of those DbContexts (remember to specify the different migration name for each DbContext). Notice that the column on the right in the linked tables above specifies the DbContext name.
- **For SqlServer you might need to add the `GO` separators**: SQL Server requires CREATE/ALTER PROCEDURE to be the first statement in a query batch. The batches are delimited by `GO`.

For example, if I'm in AdminUI version 9.1.1 and I want to run the latest migrations, this is the command I would run:

```bash
dotnet ef migrations script 20250126152936_ClaimValueSearchRepeatedResultsBugFix --context SqlServerIdentityDbContext --output ./Migration_Scripts/SqlServer/Identity.sql
```

This will generate the Identity migrations from that migration until the latest as I have not specified a second migration name to stop at. At the time of writing this is version 12.0.1 so I would not need to run more scripts as there are no different DbContexts down the line in the table.

Notice that we have specified the starting migration name of version 9.1.1, and the command will not include this migration but the next ones.

You can verify which migrations are included in the script generated by searching for `EFMigrationsHistory` in the script. After the script of each migration you will find some code like this that enters the name of the migration just run in the migration history table:

```sql
INSERT INTO [__EFMigrationsHistory] ([MigrationId], [ProductVersion])
VALUES (N'20260415105540_StoredProcedureRefactorWithoutBigCount', N'10.0.8');
```


## To run ALL the migrations

If you want to run the entire migration scripts this is the right order to do so:

1. Duende - Configuration: Default Duende migration. You don't need if you have generated them already. 
2. Duende - Operational: Default Duende migration. You don't need if you have generated them already. 
3. AdminUI - Extended configuration: Essential for running AdminUI.
4. AdminUI - Audits: This is needed for audits tab.
5. ASPNETCore - Identity: You don't need it if you use custom identity or have generated them already.
6. RSK - SAML Artifacts: You don't need it if you don't want to use SAML.
7. RSK - SAML Configuration: You don't need it if you don't want to use SAML.
8. RSK - WSFederation: You don't need it if you don't want to use WSFederation.
